# 게시판 글·이미지 자동 게시

2026-10-20 사용자가 승인한 운영 방식: 다음 글부터 별도 승인 없이 게시하고 하루 약 10편을 꾸준히 올립니다. 기존 화·금 PR 승인 방식은 예약 작업에서 사용하지 않습니다.

화면에서 따라 하는 사용량·비용 확인과 실제 비용 예시는 [2026-10-20 작업 기록](../docs/WORK_LOG_2026-10-20.md)에, 예약 지연 보완과 현재 일정은 [2026-10-21 복구 기록](../docs/AUTOMATION_RECOVERY_2026-10-21.md)에 정리했습니다.

## 일정과 게시 흐름

- 게시 목표는 한국 날짜별 하루 10편을 24시간에 분산합니다. 목표 시각은 00:17, 02:41, 05:05, 07:29, 09:53, 12:17, 14:41, 17:05, 19:29, 21:53으로 144분 간격입니다. Cloudflare는 24시간 5분 간격으로 부족분을 확인하고, GitHub Actions는 UTC `17 * * * *`로 매시 17분에 보완합니다. 목표 시각은 생성 시작 기준이며 실제 공개는 검수·배포에 따라 늦어질 수 있습니다.
- 이미 해당 시간대 목표를 채웠으면 유료 API를 호출하지 않습니다. 지연·검수 보류·오류로 부족하면 다음 점검에서 다른 주제로 한 편씩 보충하며, 마지막 목표 뒤에도 자정 전까지 보충합니다. 한국 시간 자정에 새 날짜의 목표·횟수를 계산하고 전날 부족분은 소급 생성하지 않습니다. 자정을 넘어 완료된 전날 생성은 공개를 보류하는 기존 보호를 유지합니다.
- 하루 실제 자동 게시 상한은 10편, 실패·보류·중단을 포함한 유료 생성 시도 상한은 15회입니다. API 호출 전에 main에 시도를 예약하므로 작업이 강제 종료돼도 한도에 포함됩니다. 예약 기록을 push하지 못하면 API를 호출하지 않습니다. 하루 15회에 도달하면 추가 비용 발생을 멈추고 원인을 확인해야 합니다.
- 중복·주제 검수 보류가 연속되면 다음 생성까지 30분 → 60분 → 최대 120분을 기다립니다. 대기 중 점검은 API 호출과 시도 예약을 하지 않습니다. 기존 당일 기록에서 대기 시각을 계산하며, 게시 성공 또는 다음 한국 날짜에 연속 보류가 끊깁니다. 한도와 게시 목표는 그대로 유지합니다. `data/editorial_status.json`의 `topicRetry`에서 대기 사유와 다음 생성 가능 시각을 확인합니다.
- GitHub 예약 작업 자체는 지연·누락될 수 있습니다. 모든 점검이 누락되거나 검수 탈락이 반복되면 10편 미만일 수 있으며, 수량을 채우려고 미검수 글을 올리지 않습니다.
- 실행 순서: 독자 질문·목차 기획 → 주제 중복 사전 검수 → 글 초안 → 문장 편집 → 본문 중복·이미지 장면 검수 → 이미지 생성 → 글·이미지 최종 검수 → main 반영 → 공개 게시글·원본 배너 확인.
- 자동 검수는 게시판 적합성, 실용성, 자연스러운 문장, 미확인 주장, 중복 내용, 이미지 의미·한글 제목·KV 로고를 확인합니다. 모든 항목을 통과한 글만 게시합니다. AI 검수는 오류를 완전히 제거하는 장치가 아니므로 게시 결과를 수시로 확인할 수 있도록 원문·검수·비용을 기록합니다.
- 검수 탈락 글은 Artifact에 보관하고 운영 게시판에는 넣지 않습니다. 다음 시간에는 다른 게시판/주제로 진행합니다. API 오류는 실패 실행으로 표시하며 받은 사용량과 오류 기록은 남깁니다.
- 새 글은 개별 URL, 목록 HTML·JSON, 최신글 JSON, 사이트맵, 해당 게시판의 메인 최신글 HTML까지 갱신합니다. 기존 글을 덮어쓰지 않습니다. 자유게시판에서 삭제한 테스트 번호도 재사용하지 않습니다.

## 게시판별 편집 방향

| 순서 | 게시판 | 내용과 이미지 방향 |
|---|---|---|
| 1 | 상품권 TIP (`gc_tip`) | 보유 상품권 관리·활용 방법과 실제 행동, 과정 중심 이미지 |
| 2 | 상품권 구매게시판 (`purchase`) | 상품 선택·판매자 확인·주문 준비, 선택과 주문 확인 장면 |
| 3 | 상품권 정보 (`gc_information`) | 종류·용어·발행사/판매처/사용처 역할, 비교와 관계 이미지 |
| 4 | 상품권 판매게시판 (`sale`) | 보유 상태·매입처 문의·정산 내역 확인, 상태와 기록 이미지 |
| 5 | 공지사항 (`general_notice`) | 사이트 이용·문의·정보보호, 해당 안내에 맞는 행동 |
| 6 | 일반상식 (`sense`) | 선물 예절·온라인 생활·정보 정리, 일상 소품 |
| 7 | 자유게시판 (`free`) | 운영팀 질문과 선택 기준, 선택지와 질문 카드 |
| 8 | 한국상품권협회 소식 (`gc_word`) | 확인된 소식만 정리, 관련 안내 자료 |

- `tools/board_profiles.py`에 글과 이미지의 게시판별 기준을 보관합니다. 마지막 자동 작성 시도 게시판 다음부터 순환합니다.
- 소식 외 모든 게시판은 새 질문·차별점·목차 후보를 기획하고 관련 본문·최근 보류 사유와 독립 비교한 뒤 하나를 선택합니다. 관심 자료가 있으면 집계된 질문을 참고하며, 관심 ID는 게시판을 바꾸어도 최근 7일간 재사용을 피합니다. 좁은 관심 질문을 소진하면 다른 구체적 독자 문제를 찾습니다.
- `tools/board_reader_tasks.json`의 질문 후보 98개(소식 외 각 게시판 14개)를 출발점으로 사용합니다. 이미 사용하거나 보류된 후보는 다시 제시하지 않습니다. 후보 수는 게시 가능한 글 수를 보장하지 않으며, 새 후보도 동일한 검수를 통과해야 합니다.
- 준비 질문을 소진하면 `tools/board_topic_pool.py`의 게시판별 새 문제 방향을 기획 입력으로 순환 공급합니다. 방향 자체는 사실 자료가 아니므로 새로운 약관·금액·업체 정책의 근거로 쓰지 않습니다. 긴 보류 설명을 창작 예시로 반복하지 않도록 기획 입력을 줄이고, 독립 검수에는 기존 비교 자료를 유지합니다.
- 선택하지 않은 후보는 `data/editorial_topic_pool.json`에 게시판별 최대 12개까지 저장합니다. 후보가 두 개 이상 남아 있으면 새 기획 API 대신 대기 후보부터 독립 검수하고, 부족할 때 기존 기획 요청 한 번으로 보충합니다. 선택 후보와 명시적 탈락 후보는 대기열에서 제거하며, 탈락 제목도 제목 중복 검사에 포함합니다. 대기 후보는 발행이 승인된 글이 아니며 본문·최종 검수를 생략하지 않습니다.
- 기획에는 독자의 구체적 상황(`reader_situation`)과 읽고 얻을 결과물(`deliverable`)을 명시합니다. 같은 넓은 소재라도 새로운 질문·해결 단계·예시가 있는지 실제 본문으로 비교합니다. 독자 호칭, 제목, 절 순서나 형식만 바꾼 글은 계속 중복으로 차단합니다. 공통 기준은 `tools/board_angle_rules.py`에 보관합니다.
- 독립 주제 검수에는 미발행 질문 목록 전체를 기존 글처럼 전달하지 않습니다. 선택한 편집 과제는 `unpublished_assignment`로 구분해 주제 적합성만 확인하고, 공개 글과의 중복 근거는 실제 경로와 본문에서 확인합니다. 준비 과제의 질문에 답한다는 이유만으로 중복으로 처리하지 않습니다.
- 미사용 과제가 있으면 기존 제목과 겹침이 적은 질문 최대 네 개를 먼저 고릅니다. 기획 API의 제목과 과제 ID를 그 목록으로 제한하고 짝도 검증해, 새 과제에 예전 글의 내용을 붙이는 것을 막습니다. 긴 실패 초안 대신 실제 게시된 독자 문제를 창작 단계에 비교 자료로 전달합니다. 본문과 독립 검수는 그대로 유지합니다.
- 전체 게시판 제목·편집 이력·보류 주제와 제목 유사도를 비교하고, 최종 검수에서도 유사 제목과 의미 중복을 확인합니다. 단어만 바꾼 재작성과 키워드 나열을 피합니다.
- 협회 소식은 `tools/board_news_briefs.json`의 사실·공개 출처·확인일·유효기간이 있는 자료만 사용합니다. 유효한 자료가 없으면 소식 게시판을 건너뜁니다. 최신 사건, 행사, 제휴, 성과를 창작하지 않습니다.
- 소식 출처는 현재 저장소에 해당 페이지가 있는 `https://kv-gift.co.kr/` 자료만 허용합니다. 자료를 추가하거나 유효기간을 바꿀 때 실제 사실과 출처부터 확인하세요.
- 공지사항에 새로운 운영시간·정책·이벤트를 만들어 내지 않습니다. 일반상식·자유게시판에는 상담 CTA를 억지로 붙이지 않습니다.
- 고객을 가장한 후기나 문의를 만들지 않습니다. 작성자는 한국상품권거래소 운영팀이며 안내 콘텐츠임을 표시합니다.
- 미확인 수수료, 매입률, 할부 조건, 처리 시간, 법적 권리, 앱 기능을 단정하지 않습니다. 전체 상품권 번호·바코드·개인정보를 공개하도록 유도하지 않습니다.

### 초안·편집 공통 문구 기준 (2026-10-22 보강)

- `board_drafts.py`의 `ARTICLE_TEXT_RULES`를 초안과 문장 편집 요청 모두에 전달합니다. 요약·소제목·본문·확인 항목 및 인용·질문·예시 전체에 적용합니다.
- 아라비아/전각 숫자와 임의 날짜를 만들지 않습니다. 날짜 확인은 `게시일`, `마지막 수정일`, `답변을 받은 시점`처럼 확인할 항목으로 설명하고, 문단 번호는 템플릿에 맡깁니다. 근거 없는 금액·기간·횟수를 한글 숫자로 바꾸는 것도 금지합니다.
- `안전한 거래` 같은 안전성 단정 대신 사업자 정보·문의 경로·상품권 취급 여부·전달 절차를 확인하는 행동을 안내합니다. 확인 절차만으로 안전이 보장된다고 표현하지 않습니다.
- 출력 전에 모든 문자열을 다시 점검하도록 요청합니다. 프롬프트만으로 무오류를 보장하지 않으며 기존 로컬 검수와 최종 글·이미지 검수는 유지합니다.
- 편집 후 금지 표현이 남으면 같은 글을 최대 한 번 추가 교정합니다. 금지 단어를 유의어나 띄어쓰기로 우회하지 않고 근거 없는 주장 자체를 제거합니다. 구조 오류는 자동 재시도하지 않으며, 교정 뒤에도 위반이 남으면 게시를 중단합니다. 교정 후 본문 중복·이미지·최종 검수를 모두 다시 거칩니다.
- 교정 요청은 추가 API 비용이 발생할 수 있습니다. 사용량은 기존 `editing` 단계 비용에 합산하고, 실행 기록의 `api_usage.context.wording_repair`와 Artifact의 `wording-repair.json`에 교정 사유·성공/실패를 남깁니다. 새로운 글 생성 시도를 예약하거나 하루 15회 한도를 늘리지는 않습니다.
- 두 실패의 증거와 보완 내역: [비용 정정 및 문구 지침 기록](../docs/COST_RECONCILIATION_2026-10-22.md).

## 이미지와 본문

- 승인된 아이보리/네이비/골드 종이 질감 일러스트를 유지하며 글의 요점에 맞춰 사물과 구도를 바꿉니다.
- 짧은 한글 제목 하나와 하단 오른쪽 KV 로고를 사용합니다. 로고는 상품권 발행사 표시처럼 상품권 위에 넣지 않습니다.
- 드라이브에서 받은 원본 로고와 승인 스타일 파일을 `tools/assets/board-banner/`에서 API에 전달합니다. 드라이브 변경본을 무검수로 자동 교체하지 않습니다.
- 이미지 모델 `gpt-image-2`, 품질 `medium`, 1536×1024 PNG가 기본입니다. 이미지 생성은 한 편당 한 번이며 자동 재시도하지 않습니다.
- 배너는 `board-img/게시판/guide-날짜-실행번호.png`로 저장합니다. 하루에 같은 게시판에 여러 편이 생겨도 파일이 겹치지 않습니다.
- 모바일에서 이미지를 자르지 않고 비율대로 표시합니다. OG/Twitter 이미지와 Article 구조화 데이터에도 같은 배너를 연결합니다.
- 글 초안·편집은 기본 `gpt-4.1-mini`, 최종 글·이미지 검수는 `gpt-5.4-mini`의 low reasoning을 사용합니다. 검수 시 후보 배너·원본 로고·승인된 스타일 이미지를 함께 비교합니다. `OPENAI_MODEL`, `OPENAI_REVIEW_MODEL`, `OPENAI_IMAGE_MODEL`, `OPENAI_IMAGE_QUALITY` Actions 변수로 변경할 수 있습니다. 다른 모델의 비용은 단가 등록 전까지 확인 불가로 남습니다.

## 실행, 검토, 중지

1. GitHub 저장소 → Actions → **게시판 글·이미지 자동 게시** → Run workflow.
2. `board=auto`는 순환 선택, 특정 게시판을 선택하면 그 게시판으로 작성합니다.
3. `preview_only=false`는 검수 통과 후 자동 게시합니다. 수동 게시도 하루 게시 10편·생성 시도 15회 한도에 포함됩니다. `catch_up=true`는 현재 시간대에서 부족한 글이 있을 때만 생성하는 복구 실행입니다. `catch_up=false`는 시간대 목표와 무관하게 한 편을 요청합니다.
4. `preview_only=true`는 글·이미지·검수·비용 파일만 생성합니다. 사이트·게시 이력·일일 자동 게시 횟수는 바뀌지 않습니다. 수동 검토 전용 생성에는 별도 API 비용이 발생합니다.
5. 실행의 `board-review-실행번호-시도번호` Artifact를 내려받아 압축을 풀고 `index.html`을 엽니다. `review.json`에 검수 결과, `result.json`에 main 반영 결과가 있습니다. 자동 검수 후 편집본과 API 원본도 함께 보관합니다.
6. 중지는 해당 워크플로 우측 메뉴 → **Disable workflow**. 실행 중인 작업도 멈추려면 해당 실행에서 **Cancel workflow**를 선택합니다. 다시 켜면 이후 점검부터 당일 부족분을 회당 한 편씩 보충하며, 지난 날짜의 부족분은 소급 생성하지 않습니다.

예약 실행은 컴퓨터를 켜 둘 필요 없이 GitHub에서 동작합니다. 공개 저장소에서 장기간 활동이 없으면 GitHub가 예약 실행을 비활성화할 수 있어 Actions 상태를 확인하세요.

같은 실행의 Re-run은 API를 다시 호출하지 않습니다. 이미 main에 게시된 실행이면 기존 글과 배너의 공개 상태만 다시 확인합니다. 생성 자체가 실패한 경우 원인을 수정한 뒤 새로운 수동 실행을 시작하세요. 검수 탈락과 동일한 주제는 자동 재사용하지 않습니다.

## 사용량과 비용 기록

- API Secret `OPENAI_API_KEY`는 GitHub Actions에서만 사용합니다. 키나 인증 헤더를 소스·PR·기록에 넣지 않습니다.
- 글 초안, 편집, 이미지 생성, 최종 검수, 필요한 경우 새 주제 생성의 원본 `usage`와 단계별 예상 USD 비용을 기록합니다.
- 자동 실행 기록: `data/editorial_runs/YYYY-MM-DD/실행번호.json`. 게시판, 주제, 게시/보류/오류, 공개 URL, 검수 결과, 전체 사용량이 들어 있습니다.
- 게시 이력: `data/editorial_history.json`. 자동 게시에는 `publication_mode=automatic`, `run_id`, 비용 기록 경로가 연결됩니다.
- 순환 상태와 보류 주제: `data/editorial_state.json`.
- 실행 기록의 `generating`은 유료 생성 전 예약된 시도입니다. 작업 종료 뒤에도 이 상태라면 강제 종료·push 실패 등을 실행 로그와 Artifact에서 확인합니다. 예약 시점에는 사용량이 없으므로 비용 0으로 해석하지 않습니다. 같은 실행을 재시도해도 새 생성은 하지 않습니다.
- Summary에 오늘 게시 수 `n/10편`과 생성 시도 `n/15회`를 표시합니다. 보충 글도 단계별 사용량과 비용을 기록합니다.
- Actions Summary와 `board-api-usage-실행번호-시도번호` Artifact에도 비용을 남깁니다. Artifact 보관은 90일이며 main에 기록된 실행 JSON은 계속 남습니다.
- 계산은 `tools/board_usage.py`의 기준 단가를 사용합니다. 예상액이며 실제 청구액, 세금, 환전은 포함하지 않습니다. 단가가 바뀌면 요율과 기준일을 갱신하세요. 응답 없는 실패 요청은 실제 과금 여부를 확인할 수 없습니다.
- 본문 생성이 끝나도 게시나 배포가 실패할 수 있습니다. 실행 기록의 published는 main에 넣은 콘텐츠를 뜻하며, 최종 **공개 게시글과 배너 확인** 단계까지 성공해야 공개 반영을 확인한 것입니다.

## 변경 충돌과 오류

- 생성 전후에 main을 최신화하고 GitHub 실행을 직렬화합니다. 일반 push만 사용하며, 동시 수정으로 push가 거절되면 강제로 덮어쓰지 않습니다. 생성된 글·이미지·비용은 Artifact에서 복구할 수 있습니다.
- 공개 확인은 HTML의 canonical·배너 경로와 이미지 원본 해시를 검사합니다. Cloudflare 반영이 늦으면 실패로 표시될 수 있으므로 main 변경과 배포 상태를 구분해 확인하세요.
- HTTP 401은 키/권한, 429는 결제·잔액·요청 제한, 403/404는 모델 권한을 확인합니다. main 보호 규칙이 자동 push를 막으면 저장소 권한 설정이 필요합니다.
- 과거 크롤링 복원 도구 `generate_boards.py`는 전체 게시판을 덮어쓸 수 있어 새 글 등록에 사용하지 않습니다.
- 이전 `run_board_draft.py`는 별도 승인 PR 작성용 수동 도구로 보존합니다. 현재 예약 워크플로는 `run_board_publish.py`를 사용하며, 과거 PR 승인 대기 제한을 적용하지 않습니다.
