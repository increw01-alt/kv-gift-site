# 게시판 자동 안내 글 운영

## 실행과 게시

- GitHub Actions의 **게시판 안내 글 자동 작성** 워크플로가 화요일·금요일 한국 시간 오전 10시에 실행됩니다. GitHub 예약 작업은 지연될 수 있습니다.
- 매회 한 편씩 게시판을 순환합니다. 순서는 상품권 TIP → 구매게시판 → 상품권 정보 → 판매게시판 → 공지사항 → 일반상식 → 자유게시판 → 한국상품권협회 소식입니다. 수동 게시 이력은 순서를 바꾸지 않으며, 자동 초안을 main에 병합한 뒤 다음 게시판으로 넘어갑니다.
- 준비된 주제가 소진된 게시판과 유효한 확인 자료가 없는 협회 소식은 건너뛰고 다음 게시판을 선택합니다. 모든 게시판에 쓸 주제가 없으면 API를 호출하지 않습니다.
- 실행마다 글 작성 Responses API 한 번, 배너 이미지 API 한 번을 호출합니다. 실패 시 자동 재호출하지 않습니다.
- 승인된 종이 질감 일러스트와 드라이브 KV 로고 원본을 함께 이미지 편집 API에 전달합니다. 네이비/골드/아이보리 스타일을 유지하면서 글 내용에 맞는 사물·구도로 한 장 생성합니다. 기본 이미지 모델 `gpt-image-2`, 품질 `medium`, 1536×1024 PNG입니다.
- 최신 승인 공지사항 배너를 스타일 참고로 사용합니다. 이미지 상단에는 글의 요점을 담은 짧은 한글 제목을, 하단 오른쪽에는 KV 로고를 넣습니다. 상품권 발행사로 오해하지 않도록 로고는 그림 속 상품권·영수증·결제카드 위에 넣지 않습니다. 참고 파일과 드라이브 출처는 `tools/assets/board-banner/README.md`에 기록했습니다. 드라이브 변경본은 자동 반영하지 않고 검토 후 교체합니다.
- Actions 변수 `OPENAI_IMAGE_MODEL`, `OPENAI_IMAGE_QUALITY`로 설정할 수 있습니다. 이미지 API 비용은 텍스트 비용과 별도이며 같은 `OPENAI_API_KEY`를 사용합니다.
- 이미지가 실패하거나 손상된 경우 글만 등록하지 않고 작업이 실패합니다. 모델 권한이나 조직 인증이 필요하면 실패 로그를 확인하세요.
- 배너는 `board-img/<게시판>/guide-날짜-게시판.png`에 저장하고, 본문 상단에 비율을 유지해 삽입합니다. 모바일에서 자르지 않습니다.
- PR에 이미지 미리보기와 생성 프롬프트를 포함합니다. 본문뿐 아니라 한글 제목의 오탈자, 로고 형태·색상·비율, 모바일 가독성과 그림의 의미를 확인 후 병합하세요. PNG 파일 검증은 이미지의 의미나 로고 정확성을 보장하지 않습니다.
- 글의 OG/Twitter 공유 이미지와 Article 구조화 데이터에도 해당 배너를 연결합니다.
- 기본 모델은 `gpt-4.1-mini`. 저장소 Actions 변수 `OPENAI_MODEL`로 변경할 수 있습니다.
- `OPENAI_API_KEY`는 GitHub Actions Secret에만 저장합니다. 키를 파일이나 PR에 넣지 않습니다.
- 결과는 별도 `auto/board-날짜-게시판` 브랜치와 검토 PR에 저장됩니다. main에 직접 게시하지 않습니다.
- PR 본문에서 글 전체를 읽고 사실관계와 문구를 확인한 후 **Merge pull request**로 병합해야 운영 사이트 배포에 반영됩니다. 리뷰 승인만으로는 게시되지 않습니다.
- 검토 대기 중인 자동 작성 PR이 하나라도 있으면 다음 실행은 건너뜁니다. 게시판의 공통 데이터 충돌과 검토 누적을 방지합니다.
- 생성을 건너뛴 경우 Actions Summary에 대기 PR 주소 또는 같은 날짜의 브랜치와 사유를 남깁니다. 이때 API는 호출하지 않습니다.
- 같은 날짜·게시판의 생성 브랜치가 있으면 다시 과금하지 않습니다. PR 생성만 실패한 경우 Actions 로그의 브랜치를 GitHub에서 수동 PR로 열면 됩니다.
- 작성일은 초안 생성일입니다. 오래 보류한 글을 병합할 때는 날짜와 내용을 검토하세요.

## 직접 실행·중지

저장소 → Actions → **게시판 안내 글 자동 작성** → Run workflow → `auto` 또는 특정 게시판 선택.

- `preview_only`를 끄면 기존과 같이 검토 PR을 만듭니다. 대기 PR이 있으면 생성을 건너뜁니다.
- `preview_only`를 켜면 글·배너·사용량 파일을 **검토용 Artifact에만 저장**합니다. PR, 게시판 목록, 운영 사이트, 게시 이력은 변경하지 않습니다. 수동 실행에서만 가능하며 대기 PR이 있어도 테스트할 수 있습니다.
- 검토 전용 실행은 실행할 때마다 글·이미지 API를 호출하므로 비용이 발생합니다. 자동 재시도는 하지 않습니다.
- 실행 완료 후 `board-review-실행번호-시도번호`를 내려받아 압축을 풀고 `index.html`을 엽니다. `banner.png`, 원문 `draft.json`, 비용 기록 `board-api-usage.json`이 함께 들어 있습니다. 검토본 보관 기간은 90일입니다.
- 검토 전용 파일은 자동으로 게시되지 않습니다. 승인받은 뒤 같은 원문·이미지를 사용해 게시용 변경을 만들 수 있으며, 이 경우 API를 다시 호출할 필요가 없습니다.

일시 중지: 같은 워크플로의 우측 메뉴 → Disable workflow.
공개 저장소에서는 오랫동안 저장소 활동이 없으면 GitHub가 예약 실행을 비활성화할 수 있으므로 Actions 상태를 확인하세요.

## 게시판별 콘텐츠 기준

| 게시판 | 작성 내용 | 이미지 방향 |
|---|---|---|
| 상품권 TIP (`gc_tip`) | 보유 상품권 관리·활용 방법과 실행 순서 | 정리 방법, 이용 과정 등 글의 핵심 행동 |
| 상품권 구매게시판 (`purchase`) | 상품 선택, 판매자 확인, 주문 전 질문 | 상품 선택·선물 준비·주문 확인 |
| 상품권 정보 (`gc_information`) | 종류·용어·발행사와 판매처 등의 역할 | 비교되는 개념과 관계 |
| 상품권 판매게시판 (`sale`) | 상품권 상태, 매입처 문의, 정산 내역 확인 | 상태 확인·문의 기록·정산 내역 |
| 공지사항 (`general_notice`) | 사이트 이용·문의·정보보호 안내 | 해당 안내에 맞는 확인 행동 |
| 일반상식 (`sense`) | 선물 예절, 온라인 생활, 정보 정리 | 해당 글과 연결되는 생활 소품 |
| 자유게시판 (`free`) | 운영팀이 제시하는 생각할 질문과 선택 기준 | 선택지·질문 카드 |
| 한국상품권협회 소식 (`gc_word`) | 확인된 운영 소식만 정리 | 실제 소식의 안내 자료 |

- 편집 기준과 이미지 방향은 `tools/board_profiles.py`에서 함께 관리합니다. 게시판 이름을 단어 뜻으로 추측하지 않고 실제 사이트의 용도를 따릅니다.
- 공지사항에는 새로운 운영시간, 정책, 이벤트를 창작하지 않습니다. 일반상식과 자유게시판에는 상담 CTA를 억지로 붙이지 않습니다.
- 협회 소식은 `tools/board_news_briefs.json`에 확인된 사실·공개 출처·확인일·유효기간이 있는 주제만 사용합니다. 현재 자료는 사용자 승인 후 실제 게시된 공지사항 보강 소식 한 건입니다. 자료가 없거나 기간이 지나면 생성하지 않습니다.
- 소식 자료를 추가할 때 먼저 사실과 출처를 확인하세요. 현재 출처 검사는 저장소에 해당 페이지가 있는 `https://kv-gift.co.kr/` 자료만 허용합니다. 만료된 자료의 날짜만 늘려 최신 소식으로 재사용하지 마세요.

- 운영팀의 자주 묻는 질문 안내이며 가상 고객 후기·가상 고객 문의로 게시하지 않습니다.
- 본문에 실제 고객 후기/접수 문의가 아니라는 안내를 표시합니다.
- 미확인 수수료, 할부 조건, 매입률, 정산 시간, 운영 시간, 법적 권리를 단정하지 않습니다.
- 금액·숫자·비율·금지 표현·HTML·외부 URL을 자동 검사하며 통과하지 않으면 PR을 만들지 않습니다. 자동 검사는 사실 확인을 대신하지 않으므로 사람의 검토가 필요합니다.
- 질문은 `tools/board_topics.json`에서 순서대로 선택합니다. 전체 게시 이력과 해당 게시판의 기존 제목 유사도를 검사합니다. 제목 유사도만으로 의미 중복을 완전히 판별할 수 없으므로 검토 때도 확인하세요.
- 준비된 주제는 구매/판매 각 12개, 상품권 TIP/상품권 정보/공지사항/일반상식/자유게시판 각 8개로 총 64개입니다. 협회 소식은 별도의 확인 자료에서 선택합니다. 소진된 게시판은 새 주제를 추가할 때까지 건너뜁니다.
- `data/editorial_history.json`은 병합된 초안의 주제 이력을 보관합니다. 삭제하지 마세요.
- 새 글은 승인된 공지사항 본문 레이아웃으로 작성하고 개별 URL, 목록 HTML·JSON, 최신글 JSON, 사이트맵에 함께 반영합니다. 메인에 해당 게시판 영역이 있는 구매/판매/자유/TIP/공지사항은 정적 최신글 HTML도 갱신합니다.
- 표 목록의 분류 열 유무와 카드 목록을 각각 보존합니다. 자유게시판에서 삭제된 테스트 글 번호는 새 글에 재사용하지 않습니다.
- 과거 크롤링 복원 도구 `generate_boards.py`는 전체 게시판을 덮어쓸 수 있으므로 새 글 등록에 사용하지 마세요.

## 사용량과 비용 확인

- 배너는 게시글 본문 상단의 이미지입니다.
- 글과 이미지 API 응답의 원본 `usage`를 각각 기록합니다. 검토 PR과 Actions 실행 Summary에 입력·출력 토큰, 모델, 예상 USD 비용, 계산 가능한 요청 합계를 표시합니다.
- 사용량 JSON에는 대상 게시판, 주제, 검토 전용/PR 생성 모드도 기록합니다.
- Actions 실행의 Artifacts에서 `board-api-usage-실행번호-시도번호`를 내려받으면 JSON 원본, 캐시 토큰 등의 상세 사용량, 적용 단가와 기준일을 확인할 수 있습니다. 보관 기간은 90일이며 PR의 표는 남습니다.
- 비용은 2026-10-20 확인한 Standard 단가로 계산한 예상액입니다. 실제 청구액, 세금, 환전 수수료는 포함하지 않습니다. 공식 요금이 바뀌면 `tools/board_usage.py`의 단가와 기준일을 갱신해야 합니다.
- 참고 일러스트와 로고를 전달하면서 발생하는 이미지 입력 토큰도 응답 사용량에 따라 비용에 포함됩니다.
- 기본 두 모델만 계산합니다. 다른 모델이나 사용량이 누락된 응답은 0원으로 처리하지 않고 확인 불가로 표시합니다.
- 이미지 생성 실패 시에도 이미 응답받은 글의 사용량은 남습니다. 응답을 받지 못한 요청은 과금 여부를 알 수 없으므로 OpenAI Usage에서 별도 확인해야 합니다.
- 글과 이미지 생성이 성공했어도 PR 생성이나 배포가 실패할 수 있습니다. JSON의 status는 API 생성 단계 상태이며 게시 상태가 아닙니다.

## 실행 오류

Actions의 실패 실행에서 오류를 확인합니다. HTTP 401은 API 키/권한, 429는 잔액·결제·요청 제한, 403/404는 모델 접근과 계정 권한을 확인합니다.
PR 생성 권한 오류는 Settings → Actions → General → Allow GitHub Actions to create and approve pull requests를 확인하세요.
PR 브랜치에는 Cloudflare 미리보기 배포가 생성될 수 있습니다. 운영 도메인 게시 여부는 main 병합과 배포 성공 여부로 구분합니다.
