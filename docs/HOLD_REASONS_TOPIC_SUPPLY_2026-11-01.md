# kv-gift 보류 코드·주제 공급 보강 대조 기록

기준 코드: `origin/main` = `8280a8843a020446372d696e5c9977265ccc2658`. 네트워크 없이 로컬 파일만 읽어 대조했다. 일반 게시판 7개에 각 5개, 총 35개 과제를 `tools/board_reader_tasks.json`에 추가했다. 기존 98개를 보존해 총 133개다. 협회 소식은 확인된 자료가 필요한 별도 경로로 유지한다.

아래는 **편집 과제**이며 새로 발행한 글이나 실제 고객 사례가 아니다. 실제 기획·본문·최종 검수를 모두 통과해야 게시할 수 있다. 현행 게시물의 약관·정책·기능 주장을 사실 근거로 재사용하지 않는다.

## 대조 방법

- 전체 게시판 목록의 제목 5,186개를 읽었다. `board_originality.existing_articles`가 분리하는 운영팀 본문 97개의 요지·해결 절차를 비교했다. 과거 이용자 메시지 본문은 수집하지 않았다.
- 아래의 가장 비슷한 글은 의미상 가까운 기존 글을 직접 골랐다. 문자열 순위의 첫 항목을 곧 의미상 가장 가까운 글이라고 간주하지 않았다. 표에 적은 차이는 새 글에서 실제로 구현해야 하는 편집 조건이다.
- 제목 검사는 기존 `fresh_topic`의 0.82 기준과, 기존 본문 검사의 5-gram 후보 포함률 0.72 기준을 제목에도 적용했다. 후자는 어휘 겹침 점검이며 의미 중복 판정이 아니다. 본문 검수의 원래 길이 조건·임계값을 낮추지 않았다.
- 35개 후보의 전체 기존 제목 대비 최대 5-gram 포함률은 **0.2000 < 0.72**, 최대 정규화 제목 유사도는 **0.4483 < 0.82**였다. 비교 수는 후보마다 기존 제목 5,186개다. 수치가 낮아도 표의 차별적 해결 내용을 실제 본문에서 구현하지 못하면 보류해야 한다.
- 새 과제의 `reader_situation`·`deliverable`은 기존 기획 검증의 12~180자 범위로 만들었다. 기획 형태로 변환해 `validate_candidates`를 거치고, 과거 과제를 소진한 임시 작업본에서 신규 과제가 실제 기획 입력에 들어가는지 검증한다.
- 과제의 제목·독자 상황·결과물이 핵심이다. 아래의 비교표·질문표라는 형식 자체를 차별점으로 삼지 않는다.

## 구현·검증의 경계

- 운영 실행 원장·상태·기존 글·일정·Actions YAML은 수정하지 않는다. 실제 API, 이미지 생성, Actions 실행, 네트워크, push, 배포는 검증에 사용하지 않는다.
- 새 코드의 `body_duplicate`는 11-01 마지막 보류 원장의 사유 문장처럼 `중복`이라는 단어가 없어도 대기에 포함된다. 테스트는 해당 원장의 메모리/임시 복사본에만 코드를 붙인다. 실제 옛 원장은 변경하지 않고 과거 문자열 규칙을 유지한다.
- 이미지 오탈자는 `image_readability`로 구분한다. `중복`이 포함된 배너 사유 문장도 신규 코드가 있으면 중복 대기에 들어가지 않는다.
- 로컬 제목·형식 검증과 사람이 수행한 본문 대조가 실제 유료 기획·편집 결과를 보장하지는 않는다. 35개가 모두 통과하거나 하루 10편을 달성했다고 보고하지 않는다.
- 원본 `.git` 쓰기 제한으로 원본 폴더의 브랜치를 만들 수 없어 `output/hold-reasons-topic-supply/`에 로컬 복제본을 만들었다. 복제본의 `origin/main`을 동일한 `8280a884`로 고정한 뒤 `fix/hold-reasons-topic-supply`에서 작업했다. 원본 main과 원본 origin 참조는 보존했다. `output/` 작업본을 배포 파일로 추가하지 않는다.
