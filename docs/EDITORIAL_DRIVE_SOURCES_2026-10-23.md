# 카카오톡 관심 주제 참고·중복 검수·검색용 이미지 정보

## 변경 범위

사용자가 지정한 Drive 카카오톡 내보내기 자료를 읽어 게시판별 자동 작성에 참고하도록 연결했다. 개별 승인 없는 기존 게시 방식, 하루 게시 목표 10편, 시도 상한 15회, 시간대별 목표, 기존 글·이미지 최종 검수와 공개 PNG 해시 검증은 유지한다.

최초 원본 확인: 2026-10-23. 자료 수정일: 2026-10-19. 인식한 메시지 54,121개에서 고정 사전의 관심 주제 18종을 집계했다. 메시지 수는 질문 수나 고객 수가 아니다. 키워드 기반 관심 분류이므로 전체 대화 의미를 AI가 분석한 결과가 아니다.

## 자료 흐름

비공개 Site Desk의 기존 일일 수집 → 지정 Drive 파일을 서비스 계정으로 읽기 → 관심 주제 ID·빈도·파일 지문·확인일만 전달 → KV 자료 갱신 workflow → 각 글의 게시판과 독자 질문 선택.

- 원문·닉네임·연락처·주문번호·쿠폰번호·대화 링크는 공개 저장소, 아티팩트, 로그, OpenAI 입력에 전달하지 않는다.
- 공개되는 `data/editorial_sources.json`에는 정해진 식별자와 숫자 집계만 허용한다. 제목이나 문장 등 임의 문자열을 넣을 수 없다.
- 관심 주제와 질문 예시는 `tools/editorial_source_catalog.json`에서 관리한다. 과거 대화는 최신 약관·가격·혜택의 사실 근거로 사용하지 않는다.
- 7개 일반 게시판은 목적에 맞는 관심 질문을 우선 활용한다. 협회 소식은 기존 검증 자료와 만료일 규칙을 계속 적용한다.
- 수집 실패 시 기존 자료를 지우지 않는다. 새 자료가 확인된 것처럼 확인일을 바꾸지 않는다.
- 실제 카카오톡 채팅방에 접속하지 않는다. 지정 Drive 파일의 새 버전만 읽는다. 새 파일 ID는 별도 등록이 필요하다.

## 글과 이미지 생성

관심 질문 기반 새 주제 제안 → 초안 → 편집 → **본문 중복·검색 의도·이미지 장면 검수** → 이미지 생성 → 글·이미지 최종 검수 → 게시 → 공개 확인.

중복 검사는 전체 게시판 제목, 유사 운영팀 글 본문, 최근 작성 의도와 이미지 장면을 비교한다. 과거 일반 회원 글의 본문은 AI 입력으로 재사용하지 않으며 제목만 비교한다. 상당한 본문 복사는 로컬 문자 묶음 비교로 차단하고, 표현이 다른 동일 질문은 별도 AI 검수에서 보류한다. 이미지 생성 전에 통과해야 하므로 중복 글에 이미지 비용을 쓰지 않는다. 자동 판별에는 한계가 있으므로 중복이 전혀 없다고 보장하지 않는다.

기존 승인 스타일과 로고 참고 이미지는 보존한다. 매 글에 구체적인 장면과 ALT 설명을 먼저 정하고 이미지 API에 전달한다. 최종 검수에서 이미지와 ALT의 일치도 확인한다. 해당 글의 작성 의도·장면·ALT를 이력에 남겨 다음 글에서 참고한다.

## 검색 접근성

- 글별 고유 제목, 한 개 H1, 질문형 H2, 요약 description, canonical, Article 구조화 데이터 유지.
- 키워드 나열과 의미 없는 반복을 금지하고 실제 독자의 질문에 답하는 절차·예시를 요구한다.
- 관련성이 있는 실제 게시글 링크를 최대 3개 추가한다.
- 배너의 구체적인 장면을 설명하는 ALT와 OG ALT를 사용한다.
- HTML img의 src와 크기 속성, 기존 모바일 반응형 레이아웃 유지.
- 신규 게시글의 이미지 URL을 이미지 사이트맵 확장으로 함께 등록한다.
- 검색 노출·순위는 보장하지 않는다. 색인 요청·실제 검색 반영은 생성과 별도다.

## 비용과 확인

관심 질문의 새 주제 제안과 이미지 전 본문 검수가 추가된다. 보통 주제·초안·편집·사전 검수·이미지·최종 검수의 6개 API 요청이며 사용량과 예상 비용은 기존 기록에 포함한다. 이미지 생성 전 보류하면 이후 요청은 하지 않는다. Drive 읽기·주제 빈도 집계는 OpenAI API를 호출하지 않는다.

`api_usage.context.source_reference`에서 참고 자료의 확인일·원본 수정일·지문을 확인할 수 있다. `originality-image-plan.json`은 해당 실행의 검토 아티팩트에 보관한다.

초기 자료는 현재 읽은 원본에서 집계했다. 서버의 지속적인 재조회 활성화 여부와 정확한 실행 결과는 비공개 Site Desk의 `docs/EDITORIAL_SOURCE_SYNC.md`에 기록한다. 원문은 KV 저장소에 추가하지 않는다.
